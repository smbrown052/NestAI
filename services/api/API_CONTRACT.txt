NestAI account API contract
==========================
All endpoints except /health, auth registration/login/reset, and /billing/webhook
require HTTP bearer authentication using the access token returned at login.
Interactive schema: GET /docs,
GET /openapi.json. Unknown JSON fields are rejected on new platform endpoints.

Persistence
-----------
GET /properties -> {"properties":[{id,external_id,kind,parsed,units,created_at,updated_at}]}
POST /analyses {text,kind,idempotency_key} -> {kind,parsed}
POST /properties {kind,parsed,idempotency_key,external_id?} -> saved property
DELETE /properties/{id} -> {deleted:id}
PATCH /properties/{id} {fees:{parking?,utilities?,pet_fee?,renters_insurance?,other?}}
-> saved property. Fees are finite nonnegative monthly amounts or null (unknown).
POST /properties/{id}/archive {} /restore {} -> saved property (is_archived:true/false).
Archived properties still count toward the saved-property cap, but do not rank/export.
These operations retain data and are account-owned/account-locked.
kind: apartment | home | rental_home. Parsing does not automatically save.
Apartment parsing delegates to the authoritative legacy text_parser (including
its 128 KB text limit), without a separate apartment parsing engine.
Normalized parser unit IDs and fractional bathrooms are retained without coercion.
Empty apartment unit extraction or a house without a matching type, address and
positive price returns 422 and rolls back analysis quotas/idempotency records.
For a stable update, reuse external_id but supply a fresh idempotency_key.
Upserts merge prior facts; omitting units preserves them. Supplying a replacement
unit list archives missing unit records instead of deleting them, and reappearing
unit IDs restore them. Archived units remain visible in saved snapshots but are
excluded from ranking/export results. DELETE is the explicit property remove action.
When external_id is omitted, a content hash is used. Unit objects need unique
nonempty STRING id, unit_number, unit_label, or unit; numeric IDs are rejected.
All saved records/units are account-owned; no legacy SQLite/session claim occurs.
GET /recovery inventories only the account's explicitly user_id-owned legacy
PostgreSQL properties/comparison snapshots. POST /recovery {idempotency_key}
performs audited, deterministic, repeat-safe recovery of those owned properties
and their home_details into account_properties. Source records remain untouched.
Existing records are retained even above today's cap; subsequent new saves remain
capped. Already recovered account records are never overwritten by re-recovery.
GET /comparisons returns only explicitly user_id-owned existing Comparison
snapshots verbatim, without assigning/dereferencing shared cache unit ownership.
Null-owned properties/comparisons, session-only records, buildings/units caches and
legacy SQLite data stay unclaimed. Administrative proof/audit is required before
any future manual ownership correction; never match solely by address/session.
Property count is shared across kinds and counts current saved properties.

GET /profile -> {preferences:object}
PUT /profile {preferences:object} -> {preferences:object}
PATCH /profile {display_name:string} -> {display_name:string|null}; trim/persist account name.
POST /requests {request:string} -> {constraints,priorities:{},summary,method}
uses shared deterministic natural-language constraints without an AI/provider call.
Unsupported/ambiguous instructions return 422; it does not invent priorities.
POST /feedback {idempotency_key,category?:bug|feature|feedback|general,title,
                description,actual_behavior?,expected_behavior?,route_or_screen?,
                user_contact_allowed?:false}
-> {id,public_reference,status}. Persists to existing feedback_reports table used
by GET /admin/feedback, without new parallel feedback storage or automatic email.
Account ownership and immutable idempotency receipt prevent duplicate submissions.
GET /entitlements -> {plan,period,timezone:"UTC",limits,usage,features,
                      legacy_credits,legacy_credits_policy}
Free: 5 analyses/month, 2 saved properties, basic comparison.
Premium: 100 analyses/month, 50 properties, 100 shared AI calls, 50 enrichment,
100 commute, 20 reports/month. Plus: 500/200/500/200/400/100 respectively.
Paid-only: advisor, negotiation, enrichment, commute, reports, exports.
Plus-only: sensitivity analytics. Advisor and negotiation share the AI quota.
Natural-language request parsing and custom lifestyle weights are paid capabilities
under features.natural_filter and features.lifestyle, enforced by the API.
Trusted persisted beta_tester grants (admin promotion or verified invite signup)
retain Premium-equivalent default features/quotas without Stripe IDs. A mere beta
plan string without the trusted persisted flag does not grant access. Existing
grants with no recorded expiry are preserved, not silently shortened/converted.
Admin PATCH /admin/users/{id}/beta-access {active:bool,expires_at?:UTC datetime|null,
limits?:{metric:nonnegative integer},features?:{known feature:boolean}} configures
grant expiry/per-account overrides independently of payment status. Expired/revoked
beta grants fall back to the actual account/subscription plan; no credits are edited.
Global beta caps use NESTAI_QUOTA_BETA_{METRIC}. Entitlements include
entitlement_source and beta_access_expires_at for explicit grant visibility.
Monthly quotas reset at UTC month boundaries; saved-property count does not.
Override limits with NESTAI_QUOTA_{FREE|PREMIUM|PREMIUM_PLUS}_{METRIC}.
Old credits, grants, purchases and referral records remain independent/unmodified.
Failures roll back quotas; repeated identical requests replay the recorded response.
An idempotency_key reused with different input/operation returns 409.
PostgreSQL account row locks serialize writes and quota consumption.
SQLite is supported only for local/testing; production concurrency needs PostgreSQL.

Comparison and paid tools
-------------------------
POST /ranking {property_ids?:string[],constraints?:object,priorities?:object}
-> {ranked:[{property_id,unit_id,property,unit,score,rank,components,confidence,
            comparison,price_num,sqft_num,beds_num,baths_num,...}],
    method,warnings}. Empty property_ids selects this account's properties.
Priorities: price,space,commute,walkability,pets (finite nonnegative weights).
Constraints: rent_lt,rent_lte,min_sqft,min_beds,min_baths,exclude_floors:[integers],
pet_friendly:bool,max_transit_walk_minutes,available_now:bool. Missing inputs do
not satisfy a requested constraint; otherwise existing neutral scorer rules apply.
Scores/filtering/comparisons reuse shared.decision and shared.constraints, also used
by the frontend. Stored profile preferences feed the same authoritative decision.
Comparison deltas are B minus A; positive rent delta means A is cheaper.

POST /advisor, /negotiation, /enrichment, /commute, /analytics, /reports:
{property_ids:string[],idempotency_key:string,question?:string,
 destination?:string,mode?:driving|walking|bicycling|transit,
 priorities?:object,constraints?:object}
Advisor/negotiation -> {provider,mock,answer,citations,warning?}
Enrichment -> {property_id,provider,mock,places,warning?}
Commute -> {property_id,provider,mock,routes,warning?}
Enrichment and commute require exactly one property and confirmed parsed.address.
Commute also requires destination. Provider errors redact credentials/upstream detail.
Enrichment returns location candidates, not invented neighborhood statistics.
Successful live enrichment/commute results are saved with the account property;
transit duration feeds the existing ranking adapter. Mock results are not promoted
into confirmed property facts.
Analytics -> {baseline,sensitivity:[{priority,priorities,winner}],method}
Sensitivity follows the shared decision function, increasing each priority to
twice its original weight plus one and reporting the scenario winner.
Reports -> {report_id,filename,media_type:"application/json",content,download_url}
Premium reports include normalized comparison scores/components and account facts.
Plus reports additionally embed shared sensitivity analytics and cost/space/peer
analysis from the same locked account snapshot.
GET /reports/{report_id}/download -> deterministic JSON attachment, same account only.
Reports are reproducible decision records, not generated/verified appraisals.
POST /exports {property_ids?:string[],format?:csv|json,scope?:properties|units,
               constraints?:shared canonical dict,priorities?:shared weights}
-> attachment bytes (not a JSON envelope). Formula prefixes in text cells are
escaped. Unit IDs remain strings; rent/size/beds/baths are finite numeric columns.
Exports call the same shared ranking/filtering with account profile preferences
and preserve ranked order. Unit scope exports only eligible units; property scope
deduplicates eligible ranked properties by their first ranked option. JSON exports
contain normalized ranked records, not unfiltered property/unit snapshots.

Provider configuration
----------------------
OPENAI_API_KEY, OPENAI_MODEL (default gpt-4o-mini); GOOGLE_MAPS_API_KEY.
Credentials are read only on the backend. All remote destinations are fixed.
NESTAI_PROVIDER_MODE defaults to live. Explicit mock is development/test-only;
mock outputs are labeled and contain no claims of live locations/travel times.
Missing credentials -> 503, upstream failure -> 502, missing facts -> 422.
NESTAI_DISABLE_EMAIL=true explicitly suppresses backend password-reset delivery;
production reset requests retain generic non-enumerating acknowledgements and never
expose provider details or claim verified email delivery. Dev links remain test-only.

Billing
-------
Paid signup creates a free account with requested_plan and pending_payment;
response includes checkout_required:true, never a mock checkout or paid activation.
POST /billing/checkout {plan:premium|premium_plus,idempotency_key,
                       trial_consent?:bool,payment_method_confirmed?:bool}
-> {checkout_session_id,checkout_url,requested_plan,active_plan,trial_days,
    price:{amount_cents,currency,recurring},payment_required_message}
GET /billing/prices -> {premium:{amount_cents,currency,recurring},
                       premium_plus:{amount_cents,currency,recurring}}
GET /billing/status -> {active_plan,requested_plan,subscription_status,
                       trial_used,trial_ends_at,cancel_at_period_end,billing_configured}
POST /billing/portal -> {portal_url}; existing subscribers use the portal.
POST /billing/webhook requires Stripe-Signature and STRIPE_WEBHOOK_SECRET.
Verified, unique Stripe events retrieve canonical current subscriptions, match
account customer + configured price, and update lifecycle atomically. Checkout
redirects and unsigned/local events NEVER activate paid access.
active/trialing grant paid features; past_due/unpaid/canceled/incomplete revoke them.
Cancel-at-period-end retains entitlement while subscription remains active.
Trial reuse does not block paid checkout; only first consented trial gets seven days.
An existing open checkout is reused for the same plan; changing plans expires it
before a new checkout is created. This prevents concurrent pending trial offers.

Optional environment: STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET,
STRIPE_PREMIUM_PRICE_ID, STRIPE_PREMIUM_PLUS_PRICE_ID; alternatively
STRIPE_PREMIUM_PRODUCT_ID / STRIPE_PREMIUM_PLUS_PRODUCT_ID resolve default_price.
STRIPE_ALLOW_LIVE=true explicitly permits live billing; default allows only sk_test.
NESTAI_STREAMLIT_URL sets checkout/portal return URLs; development defaults localhost.
No price is created/changed or inferred from conflicting UI/mock/docs amounts.
Configured prices are retrieved read-only; missing config yields 503 not startup crash.

Deployment and validation
-------------------------
Set DATABASE_URL to PostgreSQL; run alembic upgrade head from services/api.
Additive migration 0007_account_services follows ae05715be4e2; 0008_beta_grants
adds nullable per-account beta expiry/quota/feature configuration without data conversion.
Start uvicorn main:app from services/api; repository shared adapters must be shipped
alongside legacy/streamlit/parser and shared.decision/shared.constraints.
Run PYTHONPATH=services/api python -m pytest services/api/tests.
Set NESTAI_TEST_DATABASE_URL to an explicit PostgreSQL test database for
migration/row-lock tests (legacy TEST_POSTGRES_URL alias is also accepted).
Each test uses a unique owned schema and cleans only that schema; otherwise
PostgreSQL tests are honestly skipped.
Automated Stripe/provider tests use mocks and do not claim live/sandbox verification.
